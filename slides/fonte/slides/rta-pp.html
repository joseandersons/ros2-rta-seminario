Análise · demais callbacks (Lemas 4 e 5, Eq. 6)

Com polling points, a prioridade deixa de proteger

sbf(A + Rᵢ) ≥ rbfᵢ(A + 1) + RBF(Cₖ \ {cᵢ}, A + Rᵢ − eᵢ + 1)

Cₖ \ {cᵢ}: todas as outras

Não há hp(i) nem Bᵢ. No pior caso, a callback chega logo após um polling point e espera a janela inteira, com qualquer prioridade.

Consequência de projeto

A ordem de registro não reduz o limite. Para proteger uma cadeia crítica, é preciso separá-la em outra reserva.

Este é o resultado central do artigo. O Lema 5 mostra que o pior caso é a callback começar logo depois de um polling point (X = 0). Por isso as callbacks de prioridade maior e menor entram igual na soma. A conclusão de projeto é usar reservas separadas para o que é crítico, que foi o que eles fizeram no move_base.
