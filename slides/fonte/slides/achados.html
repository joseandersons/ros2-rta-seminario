A ordem dentro do tipo varia entre execuções. A causa está no código do rclcpp: as callbacks ficam num std::unordered_map.

Este é o slide que responde “o conteúdo continua válido?”. É a comparação do mesmo código dos autores em duas versões do ROS 2: o resultado no Crystal é o que eles publicaram no artigo (Figura 3); o resultado no Jazzy é o que obtivemos rodando o mesmo código hoje, só com ajustes de API para compilar. A essência do modelo continua, mas duas premissas caíram. O Lema 3 (timers privilegiados) não vale mais: os timers caem na Eq. 6, como as demais callbacks. E a prioridade por ordem de registro deixou de existir no Jazzy: os subscribers foram registrados como high, medium, low, mas rodaram medium, low, high ou low, medium, high, variando entre execuções. A comunidade registrou isso na issue ros2/rclcpp#2532, aberta por alguém que rodou o próprio código dos autores do artigo.
